# ADR-0002：自建轻量 Web 标注台，不部署 CVAT / Label Studio

- **状态**：已接受（2026-09）
- **相关**：02-architecture、04-annotation-workflow、07-ui-spec、10-oss-survey

## 背景

需求明确"支持人工标注与模型辅助标注"，且整体要求**轻量级**。可选路径：

| 方案 | 特点 |
|---|---|
| A. 自建轻量 Web 标注台（Canvas + 本项目 API） | 与训练/数据集/门禁同一套数据模型；可定制预标注交互；无额外部署 |
| B. 部署 CVAT | 功能全、支持自动标注；但需 Docker Compose 多容器、Postgres、Redis，资源占用大 |
| C. 部署 Label Studio | 单体 Python 服务较易部署；但需 ML backend 才能预标注，且与本项目数据模型重复 |
| D. 桌面工具 X-AnyLabeling | 开箱即用的模型辅助；但 GPLv3、桌面端、无法与任务队列/审计/冻结闭环 |

## 决策

**以 A 为主**：自建轻量 Web 标注台（Vite + React + Konva），与 API/数据库同源。
**B、C 不采用**。**D 作为可选外部工具**：仅通过 LabelMe JSON 格式互通，用于大规模重标注或离线场景。

## 理由

1. **闭环价值**：预标注、来源标记（model/model_edited）、审计、数据集冻结、权重门禁必须共享同一数据模型；外部平台无法提供这套组合。
2. **资源约束**：本机 RAM 15GB、磁盘余量 27GB；CVAT 全栈会让"轻量"目标落空。
3. **交互定制**：裂缝场景需要"复制上一帧""掩膜提示""亮度/对比度调节""低置信度可视化"，自建成本低于二次开发外部平台。
4. **许可**：自建不受 GPL/AGPL 传染（仅训练依赖 AGPL，边界清晰）。

## 后果

- 正面：安装即用（单进程 + 静态资源）、标注数据零转换、可深度定制。
- 负面：需要自研画布交互（框/掩膜/快捷键），预计 3–5 人日；缺少多人实时协同（首版单用户可接受）。

## 替代方案（若将来需要多人协同）

在 M5 之后评估：保留本项目数据模型，把标注台替换为"CVAT + 适配器（导入导出 + Webhook）"，或将 FastAPI 换 Postgres 后自建多用户版本。数据格式与冻结逻辑不变。
