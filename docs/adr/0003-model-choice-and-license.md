# ADR-0003：检测模型选型与许可边界

- **状态**：已接受（2026-09）
- **相关**：05-model-plan、08-deployment、10-oss-survey

## 背景

首版需要：训练便捷、预标注快、导出 ONNX 顺畅、小样本可用。候选：

| 方案 | 许可 | 优点 | 缺点 |
|---|---|---|---|
| **Ultralytics YOLO11** | **AGPL-3.0** | 训练/评估/导出/预标注一体化，文档与社区最好 | AGPL 对闭源分发有传染性 |
| RTMDet（MMDetection） | Apache-2.0 | 许可宽松、小目标较强 | 训练与导出链更重，预标注集成需自建 |
| YOLOX | Apache-2.0 | 轻量、部署简单 | 生态与工具链不如前者 |
| YOLO-World / GroundingDINO | Apache-2.0 / AGPL（各版本不同） | 开放词表，可零样本 | 精度与速度不及专用检测器 |

用户已确认：**内部自用，不限制许可**。

## 决策

1. 首版训练与推理（含预标注）使用 **Ultralytics YOLO11n/s**。
2. 将 ultralytics 视为**可替换的"训练/预标注引擎"**，通过 `Detector` 抽象隔离：接口仅 `load(model_path)` / `predict(images, conf, iou)`。
3. 记录 AGPL 边界：**仅**训练脚本与预标注服务依赖 ultralytics；工作站服务、标注台、数据治理、边缘推理（ONNXRuntime）均不依赖。
4. 若将来需要闭源分发：按 §替代方案切换骨干并重训，**数据格式、标注、数据集冻结、边缘包格式全部不变**。

## 理由

- 首版目标是"尽快跑通闭环 + 小样本出结果"，ultralytics 的工程效率优势明显；
- 隔离层（`Detector`）使替换成本限定在 1 个适配器 + 1 次重训；
- 边缘端只跑 ONNX，导出后不再依赖训练框架，许可面自然收敛。

## 后果

- 正面：M2/M3 开发最快；ONNX 导出与量化路径成熟。
- 负面：若未来闭源商用，需要重训（预计 1–2 人日 + 一次训练）。

## 替代方案（迁移清单）

| 步骤 | 动作 |
|---|---|
| 1 | 新增 `prelabel/detector_rtmdet.py`（或 YOLOX）实现同一接口 |
| 2 | 训练脚本切换为 MMDetection / YOLOX 配方（数据目录结构不变，`data.yaml` 转换器已具备） |
| 3 | 用冻结测试集对齐指标（目标：差距 ≤ 1 mAP50，否则调整配方） |
| 4 | 导出 ONNX 后按 M4 流程重新生成边缘包 |
| 5 | 移除 ultralytics 依赖，更新 `docs/10-oss-survey.md` 与本文状态 |
