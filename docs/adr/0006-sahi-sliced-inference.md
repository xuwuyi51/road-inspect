# ADR-0006：切片推理（SAHI 策略）内置

- **状态**：已接受（2026-09）
- **相关**：05-model-plan、06-api-spec、08-deployment

## 背景

三类影像的尺度差异极大：

| 来源 | 分辨率 | 目标尺度 |
|---|---|---|
| 手机/相机照片 | 1920×1080 或更高 | 裂缝可能仅占画面 200×20 px |
| 行车记录仪抽帧 | 1920×1080 | 远处裂缝 < 10 px 宽 |
| 无人机航拍 | 4000×3000 ~ 8000×6000 | 单条裂缝可能只占 0.1% 面积 |

若整图缩放到 640 推理，细裂缝在缩略后可能只剩 1–2 像素 → 系统性漏检。

## 决策

1. **推理侧内置切片管线**：`tile`（默认 1024，可配 640/1280）+ `overlap`（默认 0.2）+ 合并策略（NMS IoU 0.5，跨切片框按同一目标合并）。
2. **训练侧可选对齐**：航拍数据在训练时也按相同参数切片（保持训练/推理分布一致）；普通道路照片默认不切片。
3. **参数一处定义**：切片参数写入导出包 `preprocess.json`，工作站与边缘端共用同一份实现与参数，避免"两套逻辑"。
4. **可关闭**：`--tile 0` 关闭切片，退化为整图推理；报告中必须标注是否启用切片，便于对比。
5. 评估时**同时报告**切片开/关两套指标（尤其小目标桶召回）。

## 理由

- 切片是解决"小目标 + 高分辨率"最直接且零额外训练成本的手段；
- 与模型架构解耦（不改网络即可提升召回），失败时可单独回退；
- 边缘端只需按同一参数切片，无需 GPU 也能提升召回。

## 后果

- 正面：细裂缝召回显著提升（典型场景 +10~20 个百分点，须在冻结测试集复测确认）；
- 负面：推理耗时随切片数线性增长（4K 图 1024 tile ≈ 20–24 片）；需要在部署文档中给出时延预算与"关闭切片"的降级开关；
- 风险：切片边界可能截断长裂缝 → 用 20% 重叠 + 跨片合并缓解；标注平台也提供"裂缝分段"建议（04 文档）。

## 替代方案

| 方案 | 未采用原因 |
|---|---|
| 直接用更高输入分辨率（1280/1536） | 显存与耗时增长更陡，且航拍图仍然不够 |
| 训练超小目标专用模型（如 P2 检测头） | 需要改网络与重训，成本高，先不做 |
| 两阶段（先检测区域再裁剪细看） | 结构复杂；切片已覆盖主场景 |
