# ADR-0004：SQLite + 文件目录 + 双哈希去重

- **状态**：已接受（2026-09）
- **相关**：03-data-model、db/schema.sql、08-deployment

## 背景

需要保存：影像（数量级 10³–10⁵）、标注（10⁴–10⁶ 行）、数据集版本、模型与运行记录、审计日志。
部署形态是**单机、单用户、离线优先**，且必须轻量（RAM < 300MB，无额外服务进程）。

候选存储：

| 方案 | 优点 | 缺点 |
|---|---|---|
| **SQLite（WAL）+ 文件目录** | 零运维、单文件、事务、支持 SQL 视图与索引 | 并发写受限（单写者）；不适合多机 |
| PostgreSQL | 并发强、可多用户 | 需要常驻服务，重 |
| 纯文件（JSON/CSV） | 最简单 | 查询/一致性/事务困难，标注审计难做 |
| 对象存储（MinIO/S3） | 适合海量影像 | 与"轻量单机"矛盾 |

## 决策

1. **元数据**存 SQLite（WAL 模式），文件（原图/抽帧/掩膜/导出）存目录树，路径以相对路径记录（`data/` 为根，可整体迁移到外接盘）。
2. 文件名使用**内容哈希或稳定 ID**，不使用用户原始文件名。
3. 去重采用**双哈希**：
   - `sha256` → 完全重复（唯一索引，幂等键）；
   - `phash`（64bit，汉明距离阈值 6）→ 近似重复（连拍/相邻帧），标记 `duplicate_of`，默认仍入库但降优先级。
4. 写入原子性：文件先写 `.tmp` 再 `rename`；标注提交为单事务；WAL 定期 checkpoint 后随备份。
5. 仅当出现**多用户并发写**或**影像量 > 50 万**时才考虑迁移 Postgres（迁移路径：`schema.sql` 基本兼容，仅需改自增与部分函数）。

## 理由

- 与"单机轻量"目标一致，不引入额外服务进程；
- 事务 + 索引 + 视图足以支撑队列、统计、审计；
- 双哈希在道路巡查场景非常关键：行车记录仪相邻帧高度相似，仅用 sha256 会保留大量冗余。

## 后果

- 正面：部署即用、备份即打包目录；查询性能对 10⁵ 级数据绰绰有余。
- 负面：并发写需串行化（服务单写者 + 任务租约已覆盖）；SQLite 文件与影像须在同一分区才能用硬链接导出（否则退化为拷贝）。

## 替代方案

| 方案 | 未采用原因 |
|---|---|
| 全 Postgres | 首版过重 |
| 影像存 DB（BLOB） | 数据库膨胀、备份不便 |
| 只存 phash 不存 sha256 | 丢失精确幂等键，重复导入无法可靠去重 |
