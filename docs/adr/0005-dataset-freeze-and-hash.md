# ADR-0005：数据集冻结与清单哈希（可复现训练的前提）

- **状态**：已接受（2026-09）
- **相关**：03-data-model、05-model-plan、09-roadmap

## 背景

项目要求"可复现、可审计"（NFR-5/NFR-6）。如果训练直接读取"当前所有已标注图片"，会出现：

- 同一命令在不同日期得到不同数据 → 指标不可比；
- 无法回答"这个权重是用哪些数据训练的"；
- 标注被后续修改后，历史评估结论失效。

## 决策

1. 训练**只接受冻结数据集**（`dataset_versions.status='frozen'`）；未冻结调用返回 `dataset_not_frozen`(409)。
2. 冻结时固化四件事并写入数据库：
   - **成员清单**（`dataset_items`：image_id + split）；
   - **类别顺序**（`class_order_json`，决定 YOLO 索引）；
   - **划分参数**（`split_json`：比例、种子、分组方式）；
   - **清单哈希** `manifest_hash = sha256(排序后的 (image.sha256, 规范化标注序列, class_order))`。
3. 冻结产物落盘 `data/datasets/<name>/`（YOLO 目录 + `data.yaml` + `manifest.sha256`），可硬链接原图以节省空间。
4. 数据集一旦冻结**不可修改**；要变更就新建版本（`ds-2026w38` → `ds-2026w39`）。
5. 模型记录强制关联 `dataset_id`，评估报告必须写清数据集版本。

## 理由

- 哈希清单使"同一数据集 + 同一配置 + 同一随机种子 → 同一结果"可验证；
- 类别顺序固化避免"类别索引漂移"这一隐蔽且致命的错误（YOLO 索引与名称错位会导致模型标签整体错乱）；
- 划分按路段分组，避免同一路段跨 train/test 造成指标虚高。

## 后果

- 正面：实验可复现、可对比、可审计；模型溯源清晰（权重 ↔ 数据集 ↔ 配置 ↔ 指标）。
- 负面：每次补数据都要新建数据集版本（有意为之）；同一张图在新旧版本中重复占用（用硬链接消除实际空间开销）。

## 替代方案

| 方案 | 未采用原因 |
|---|---|
| 直接读"当前标注状态"训练 | 不可复现、指标不可比 |
| 用 DVC/git-lfs 管理数据集 | 引入额外工具链，且与单机轻量目标冲突（可在有 NAS 后评估） |
| 只记录时间戳不记哈希 | 无法检测标注被修改，审计价值不足 |
