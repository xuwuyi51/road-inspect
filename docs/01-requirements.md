# 01 · 需求规格（Requirements）

## 1. 角色

| 角色 | 关心什么 | 主要操作 |
|---|---|---|
| 巡检员（采集） | 今天拍了/录了哪些路段，能不能直接上传 | 上传照片/视频/航拍图，看导入结果与定位 |
| 标注员 | 标得快、模型能帮我打草稿 | 人工标注、修正预标注、批量复制同路段标签 |
| 复核员 | 标签是否一致、有无漏标误标 | 抽检、打回、一致性统计 |
| 算法/运维 | 数据能不能复现、模型有没有变好 | 冻结数据集、启动训练、看指标、门禁、导出模型 |
| 边缘使用者 | 现场能不能离线跑、结果能不能导出 | 运行 `rdinspect infer`，拿 JSONL/CSV 结果 |

## 2. 典型场景（端到端）

**S1 手机照片快检**：巡检员沿路拍 200 张照片上传 → 系统读 EXIF 时间/GPS、去重 → 生成待标注任务 → 标注员先在标注台点"载入预标注"得到粗框 → 逐张修正为四类 → 复核员抽检 20% → 冻结为 `ds-2026w38`。

**S2 行车记录仪视频**：上传 30 分钟 1080p 视频 → ffmpeg 抽帧（默认 2fps，可配）→ pHash 去重（相似度 > 0.95 丢弃）→ 与 GPS 轨迹（CSV/SRT）按时间对齐 → 生成任务。

**S3 无人机航拍**：上传 8000×6000 大图 → 按 1024 切片（重叠 20%）生成 tile 任务 → 标注后训练时使用相同切片策略；推理时用 SAHI 合并结果。

**S4 模型辅助迭代**：用现役模型对新增 1000 张做预标注 → 标注员只改错 → 冻结新数据集 → 训练 → 若测试集 mAP 不低于现役则通过门禁 → 导出 ONNX → 车载设备更新。

**S5 边缘现场**：巡检车把模型与配置拷到 `rdinspect` 目录，插入相机 SD 卡 → `rdinspect infer --input /mnt/sd --out ./out` 生成 JSONL（含类别、置信度、框、时间戳）→ 回到办公室导入工作站复核。

## 3. 功能需求

### FR-1 采集与导入
- FR-1.1 支持目录/多选上传照片（jpg/png/heic 可转码）、视频（mp4/mov）、航拍大图（tif/jpg）。
- FR-1.2 照片解析 EXIF：拍摄时间、GPS 经纬度、设备型号；无 GPS 时允许手工补录路段号。
- FR-1.3 视频抽帧：可配 fps、起止时间、最大帧数；输出帧带时间戳。
- FR-1.4 去重：SHA256 完全重复直接丢弃；pHash 汉明距离 ≤ 阈值视为近似重复，标记为 `duplicate_of`。
- FR-1.5 大图切片：按 tile 尺寸/重叠切片，保留原图与切片映射（原图坐标 ↔ tile 坐标）。
- FR-1.6 导入批次（batch）记录：来源、数量、跳过原因统计，可回滚。

### FR-2 标注台（人工标注）
- FR-2.1 矩形框绘制/移动/缩放/删除；快捷键：数字选类、`D`/`A` 上下一张、`W` 保存、`Esc` 取消。
- FR-2.2 类别选择器由类别注册表驱动（新增类别自动出现，无需改前端）。
- FR-2.3 同路段/相邻帧"复制上一张标签"（视频抽帧场景提效）。
- FR-2.4 裂缝类可选掩膜模式：点/框提示 → 生成掩膜 → 橡皮擦修正。
- FR-2.5 画布支持缩放、平移、亮/对比度调整（暗光与逆光影像可判读）。
- FR-2.6 每张图的状态与耗时记录，支持按状态/类别/批次过滤任务队列。

### FR-3 模型辅助标注
- FR-3.1 单张/批量预标注：调用现役检测模型生成候选框（可设置信度阈值）。
- FR-3.2 预标注结果与人工标注**可区分来源**（`source=model|human|model_edited`），用于后续分析。
- FR-3.3 垃圾类支持零样本预标注（开放词表模型），结果同样可修正。
- FR-3.4 掩膜辅助：框选/点选调用 SAM 生成裂缝掩膜，人工确认后入库。
- FR-3.5 预标注失败/超时不影响人工标注流程（降级为纯人工）。

### FR-4 复核与质量管理
- FR-4.1 复核队列：按随机抽检比例或"低置信度优先"生成。
- FR-4.2 打回原因分类（漏标/错类/框不准/掩膜不准），可退回原标注员。
- FR-4.3 一致性统计：同一图被两人标注时的 IoU/类别一致率、Cohen's Kappa。
- FR-4.4 审计日志：谁在何时改了什么（标注的增删改均留痕）。

### FR-5 数据集与版本
- FR-5.1 按条件选样（类别、批次、时间、复核状态）生成数据集草稿。
- FR-5.2 冻结：生成不可变 `dataset_version`，含图片清单、标注、类别、train/val/test 划分与**哈希清单**。
- FR-5.3 导出格式：YOLO（Ultralytics `data.yaml`）、COCO JSON、LabelMe/X-AnyLabeling JSON。
- FR-5.4 导入外部标注：支持上述三格式回灌（用于接入公开数据集或外部工具成果）。

### FR-6 训练与评估
- FR-6.1 一键训练：读取冻结数据集 + 训练配置（模型规格、epochs、imgsz、增强、batch），后台任务执行并实时输出日志。
- FR-6.2 评估：分类别 mAP50 / mAP50-95 / 精确率 / 召回率；裂缝类额外报告按掩膜派生的宽度分布（若有掩膜）。
- FR-6.3 混淆分析：类别间混淆矩阵与误检样本导出（便于补数据）。
- FR-6.4 门禁：候选权重必须在冻结测试集上不低于现役权重（可配容差），否则标记为"未通过"并保留原因。

### FR-7 模型与导出
- FR-7.1 模型注册表：名称、版本、训练数据集版本、指标、状态（candidate/validated/production/archived）、文件路径与哈希。
- FR-7.2 导出：ONNX（opset 可配，动态 batch/尺寸可选）；可选 TensorRT 引擎（边缘机生成）。
- FR-7.3 导出包：模型 + `labels.yaml`（类别顺序与阈值）+ `preprocess.json`（归一化/切片参数）+ 版本清单，供边缘端直接使用。

### FR-8 边缘离线推理
- FR-8.1 `rdinspect infer` 支持输入目录（图片）、视频文件、RTSP 流（可选）。
- FR-8.2 输出 JSONL/CSV：`{image, ts, gps?, detections:[{class, conf, bbox}], model_version}`。
- FR-8.3 无网络运行；不依赖浏览器与数据库（配置来自同目录 JSON/YAML）。
- FR-8.4 切片推理：大图/高分辨率自动 tile + NMS 合并，参数可配。
- FR-8.5 性能预算：640 输入下 CPU ≥ 15 FPS（YOLO11n ONNX，4 线程）或 GPU ≥ 100 FPS；显存占用 < 2GB。

### FR-9 统计与报表
- FR-9.1 按批次/时间/路段统计各类灾害数量、平均置信度、检出率。
- FR-9.2 导出 CSV/JSON；预留 GIS 所需字段（经纬度、方位、路段号）。

### FR-10 类别扩展
- FR-10.1 通过注册表新增类别（代号、中文名、颜色、父类、是否裂缝类）。
- FR-10.2 新增类别后：标注台自动可选；数据集/导出自动携带；训练配置自动更新 `nc` 与名称顺序（顺序变化视为新数据集版本）。

## 4. 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | 轻量 | 服务常驻内存 < 300MB（不含训练）；安装依赖 < 1.5GB；无 K8s/对象存储 |
| NFR-2 | 启动速度 | 工作站服务冷启动 < 5s；标注台首屏 < 2s（局域网） |
| NFR-3 | 单机可用 | 单机单用户全流程闭环；SQLite WAL；无需账号系统 |
| NFR-4 | 离线 | 除数据/模型下载外，全流程可离线运行 |
| NFR-5 | 可复现 | 冻结数据集 + 配置 + 随机种子 + 权重哈希，可复现同一评估结果（容差内） |
| NFR-6 | 可审计 | 标注增删改、模型状态变更全部留痕 |
| NFR-7 | 可移植 | 工作站与边缘共用模型契约；边缘端为纯 CLI + ONNX |
| NFR-8 | 性能 | 预标注 640 输入 GPU ≥ 60 FPS（YOLO11n）；单张预标注 < 200ms |
| NFR-9 | 稳健 | 导入/预标注失败不阻塞主流程；任务可重试且幂等（按文件哈希） |
| NFR-10 | 安全 | 仅监听本机/内网；上传限制大小与类型；路径穿越防护 |

## 5. 状态机

```
任务(image)：pending → prelabeling → prelabeled → annotating → annotated → reviewing → approved
                                   ↘ (跳过预标注) ↗                    ↘ rejected → annotating
数据集(dataset_version)：draft → frozen → (used by N runs) → archived
模型(model_version)：candidate → validated → production → archived
训练任务(run)：queued → running → succeeded / failed / canceled
```

## 6. 验收标准（按里程碑）

| 里程碑 | 可验证验收 |
|---|---|
| M1 采集+标注 | 上传 500 张照片与 1 段视频 → 去重/抽帧正确；标注 4 类各 50 张并导出 YOLO/COCO/LabelMe，三格式互转后类别与框坐标误差为 0 |
| M2 模型辅助 | 预标注可一键载入并修正；标注来源可区分；SAM 掩膜在裂缝样本上可用 |
| M3 训练闭环 | 3–5k 张小样本训练完成；分类别 mAP50 报告；门禁逻辑生效（构造劣化权重被拒） |
| M4 边缘推理 | 导出 ONNX 后在无网环境对 200 张图批量推理；JSONL 结果与工作站同模型结果一致（容差 1e-3）；满足 NFR-1/FR-8.5 预算 |
| M5 迭代扩展 | 新增第五类（如网裂）不改代码即可标注、冻结、训练、导出 |

## 7. 约束与假设

- 内部自用，不限制许可证选择（首版用 ultralytics AGPL / X-AnyLabeling GPLv3 做标注辅助），若将来闭源分发需按 ADR-0003 替换。
- 首版单用户、单机；不考虑并发多人实时协同（仅串行任务分派）。
- 数据集容量首版 3–5k 张（磁盘 27GB 约束）；扩容方案见 08-deployment。
- 灾害判定以图像证据为准，不含路面三维形变与结构内部病害。
